# خريطة رحلة العميل — دفتر

## متى تستخدمها
- لفهم كيف ينتقل العميل من الاكتشاف → التسجيل → القيد الأول → الاستمرار.
- عند تسرّب العملاء في مرحلة معيّنة (التسجيل، الدخول بالجوال، onboarding، التفعيل).
- عند تصميم تدفّق جديد أو تحسين onboarding.
- عبارات مثل: «وين أخسر العملاء»، «ارسم القُمع»، «تجربة العميل».

## المبدأ الأساسي
كل مرحلة لازم تحتوي: ماذا **يفعل** العميل، وماذا **يفكّر**، وماذا **يشعر**، و**الفجوة** بين توقّعه والواقع. الفرق بين خريطة رحلة وقُمع عادي هو **المشاعر**.

## اربطها بالواقع أولاً (مصدر الحقيقة)
قبل الرسم، استخرج أحداث التحليلات الفعلية بدل التخمين:
```bash
grep -roE "track\(['\"][^'\"]+" apps/web --include='*.tsx' | sort -u
```
الأحداث الحالية في دفتر (لقطة نوفمبر ٢٠٢٦ — شغّل الأمر أعلاه لأحدث قائمة): `landing_viewed` · `cta_clicked` · `exit_survey_shown/answered/dismissed` · `login_started` · `login_method_selected` · `login_failed` · `otp_stage_reached` · `user_signed_in` · `user_signed_up` · `onboarding_started` · `onboarding_completed` · `first_expense_prompt_viewed/clicked/skipped` · `first_expense_completed` · `product_created` · `workflow_started` · `workflow_failed`. (لا يوجد حدث إحالة/توصية بعد.)
لقراءة الأرقام الفعلية: استخدم وكيل `kpi-analyst` أو استعلام SELECT على قاعدة الإنتاج (SELECT فقط — راجع `ops/CHARTER.md`).

## المراحل الست (مكيّفة لدفتر والسوق السعودي)

| المرحلة | هدف العميل | السؤال المفتاحي | حدث التحليلات |
|---|---|---|---|
| **الوعي** | يدرك إن عنده مشكلة (ما يعرف ربحه) | كيف سمع عن دفتر أول مرة؟ | `landing_viewed` |
| **التفكير** | يقارن دفتر بالدفتر الورقي/Excel/محاسب | وش يوقفه عن التسجيل؟ | `cta_clicked` |
| **القرار** | يسجّل ويدخل بالجوال | وش يحفّز «سجّل محلك»؟ | `login_started` · `otp_stage_reached` · `user_signed_up` |
| **الإعداد (onboarding)** | يسجّل بيانات المحل ويوصل لأول قيمة | كم بسرعة يسجّل أول قيد؟ | `onboarding_completed` → `first_expense_completed` |
| **الاحتفاظ** | يرجع ويسجّل بانتظام | ليش يستمر أو يسكت؟ | نشاط متكرر (قيود/فواتير) |
| **التوصية** | يرشّح دفتر لصاحب مشروع ثاني | وش يخلّيه يحكي عنه؟ | (لا يوجد حدث بعد — فجوة) |

## لكل مرحلة وثّق
1. **نقاط التماس** — كل تفاعل (إعلان، صفحة هبوط، OTP، شاشة، رسالة واتساب).
2. **الأفعال** — ما يفعله حرفياً.
3. **الأفكار** — أسئلته ومخاوفه (بالعامية السعودية).
4. **المشاعر** — متحمّس، محتار، قلقان، مبسوط.
5. **نقاط الألم** — الاحتكاك والتشويش.
6. **الفرص** — فجوات ممكن تحسّنها.

## حدّد الفجوات الحرجة
- **نقاط التسرّب** — وين يطلع ولا يرجع (ركّز على فجوة `onboarding_completed` ناقص `first_expense_completed` = حسابات صامتة، أولوية `activation-coach` رقم ١).
- **هبوط المشاعر** — وين يتحوّل الشعور من إيجابي لسلبي.
- **نقاط تماس ناقصة** — مراحل بلا تواصل استباقي.
- **فشل التسليم** — وين ينتقل بين أنظمة ويضيع السياق (مثال: Authentica للدخول بالجوال).
- **فجوات زمنية** — وين يمر وقت طويل بين تفاعلين.

## المخرج
أخرِج خريطة نصية كاملة بالتنسيق أدناه + قائمة ٣-٥ تحسينات مرتّبة بالأثر مقابل الجهد. المخرجات في ملف داخل المشروع (مثل `docs/ux-persuasion/` أو `ops/runs/$(date +%F)/`) وأرسله للمؤسس.

## قيود
- **لا تختلق بيانات عملاء** — أي افتراض بلا رقم فعلي اكتب جنبه `افتراض — يحتاج تحقق`.
- **دايماً ضمّن المشاعر**.
- **دايماً أخرِج قائمة تحسينات مرتّبة**.
- بيرسونا واحدة لكل خريطة (صاحب محل صغير / أسرة منتجة / فريلانسر) — إذا تعدّدت، خرائط منفصلة.
- كل مرحلة ٦-٨ أسطر كحد أقصى. نص فقط، بلا صور.
