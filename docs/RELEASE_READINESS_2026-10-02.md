## النطاق
الويب وPWA على Cloudflare Pages، وخادم Supabase Edge وPostgreSQL. اختبارات الكتابة استخدمت حسابين صناعيين في فرع staging-qa المعزول `ymbkhhsberlweckijuzm`؛ لم تُعدل بيانات مستخدمي الإنتاج. المشروع الحي `nklcbcpkycrhuumpbksb` فُحص للقراءة فقط.
تطبيق Native وخادم NestJS القديم ليسا إصدار الويب الجاري. OTP وOCR والخدمات غير المنفذة لا تُعد ميزات مقبولة لهذا الإصدار.

- استخدام تاريخ الشراء في التقارير؛ إرجاع خطأ واضح عند فشل استعلام التقرير بدلاً من أصفار مضللة.

## بوابات تمنع الاعتماد النهائي للإنتاج
1. تأكيد وجود نسخة احتياطية حديثة فعلية لمشروع الإنتاج، وتوثيق وقتها ونجاح استعادتها إلى مشروع معزول، مع قياس مدة الاستعادة والتحقق من المستخدمين والفواتير والمخزون والصلاحيات والدوال. خطة المؤسسة Pro مؤكدة، لكن سجل النسخ وإجراء استعادة الإنتاج غير متاحين في الاتصال الحالي. نسخة قاعدة البيانات لا تتضمن ملفات Storage؛ يلزم تحقق منفصل لها إن استُخدمت.
2. إنشاء فرع اختبار نظيف يمر بسلسلة migrations عند إعادة التحقق قبل النشر. فرع staging-qa كانت حالته MIGRATIONS_FAILED رغم نجاح الاختبارات المباشرة، وحُذف بعد انتهاء الاختبارات بناءً على طلب صاحب المشروع لتوقيف التكلفة.
3. تشغيل حمل بحجم بيانات الإنتاج وهدف مستخدمين متفق عليه؛ عتبة p95 ≤ 3 ثوانٍ المستخدمة هنا حد أولي فقط. تحديد RPO/RTO واعتمادهما قبل وعد التوافر.
4. قرار المالك اعتمد عرض الرقمين معاً: الربح من المبيعات = المبيعات − تكلفة البضاعة المباعة − المصاريف؛ النقد الداخل والخارج = المبيعات − كل المشتريات − المصاريف. نُفذ محلياً مع التنبيه لتكلفة المنتجات غير المرتبطة بالمخزون، ويظل قبول المستخدم للمسارات الأساسية وGoogle Login وتجربة الهاتف والمتصفحات المستهدفة. لم يُجرَ SAST/DAST شامل أو اختبار Native في هذه الجولة.

## ترتيب النشر بعد إغلاق البوابات
1. حفظ النسخة الاحتياطية ومصدر Edge الحالي ونسخة نشر Cloudflare الحالية؛ توثيق معرفاتها وخطة الرجوع.
2. تطبيق `supabase/migrations/20261002103135_invoice_paid_amount_atomic.sql` على الإنتاج أولاً. هذه الهجرة اختُبرت على staging قبل حذفه، ولم تُطبق على الإنتاج. تحقق أن إنشاء PAID يُرجع ويحفظ paidAmount = total، وأن تجاوز المخزون يتراجع بالكامل. لا تستخدم ملفات fixture SQL على الإنتاج.
3. نشر `supabase/functions/api/index.ts` مع الإعدادات الحالية للمصادقة المخصصة؛ لا تضف سماح localhost في الإنتاج. نسخة staging النهائية 30 أزيل منها سماح localhost المؤقت، ونجح تحقق تسجيل الدخول وملخص المبيعات 60 والربح 54 بعد نشرها.
4. نشر حزمة Cloudflare الثابتة بعد تحديد NEXT_PUBLIC_API_URL لمشروع الإنتاج وبيئة التطبيق production. لا تنشر `.next-release-check` فهو يتصل بـstaging. الحزمة المعدة `outputs/release-candidate-2026-10-02/web-static.tar.gz` تستخدم API الإنتاج.
5. إجراء Smoke بإشراف مالك الحساب: تسجيل دخول، إنشاء شراء وفاتورة ببيانات اختبار معلّمة، السداد، فحص المخزون والتقرير والعزل، دون إرسال رسائل للعملاء.
6. مراقبة 24 ساعة: أخطاء 5xx، زمن p95، فشل الحفظ، فروق paidAmount/total وأرصدة المخزون. أي تسرب بيانات أو خلل مالي يمنع التوسع ويُصعّد فوراً؛ التوقف عن نشر المزيد، حفظ السجلات، والتصحيح أو الرجوع إلى الإصدار المحفوظ. الهجرة الإضافية متوافقة مع المصدر السابق؛ لا تحذف بيانات أو حركات مخزون للرجوع.
