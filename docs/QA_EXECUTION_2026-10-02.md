## الإصلاحات المنفذة

- أُضيف حاجز خادمي افتراضي الإغلاق لمطلبي OTP إرسالًا وتحققًا. لا يعمل دخول الجوال إلا عند ضبط `PHONE_LOGIN_ENABLED=true` في إعداد Edge Function؛ يبقى غير مضبوط حاليًا حسب قرار المنتج.
- عُدلت اختبارات API لتغطي إيقاف OTP على الخادم، وتوثق حدّ المعدل العام وحدّ الهوية معًا.
- وُثّق إعداد الدخول بالجوال في `docs/PHONE_LOGIN_SETUP.md`.

## نتائج تستدعي قرارًا قبل الإصدار

1. **التطبيق الأصلي:** شاشة دخول Expo في `apps/mobile` تطلب رقم الجوال ورمز OTP فقط. بعد إيقاف OTP ستفشل المصادقة فيه. يلزم إما استبعاده صراحة من الإصدار الحالي أو تنفيذ دخول البريد له واختباره على أجهزة فعلية.
2. **رحلة البيانات:** يلزم حسابان تجريبيان ومنشأتان في STAGE لاختبار التسجيل والتحقق، الفاتورة/المخزون، الشراء، المصروف، والتقارير مع التحقق من العزل وعدم التكرار.
3. **RLS:** السياسات تبدو مقيدة بحسب المنشأة في migrations، لكن لم تُشغّل اختبارات SQL بصلاحيتي `anon` و`authenticated` على مشروع منفصل.
4. **الأداء والأمن الديناميكي:** يلزم تشغيل k6 وZAP على STAGE فقط، مع حدود استخدام وتنبيه تكلفة.
5. **CI:** يوجد ملف `.github/workflows/ci.yml` في نسخة العمل لكنه غير متعقب في Git حاليًا؛ لم أغيّر ملكيته أو أضفه إلى الفهرس، لذلك لا أعد تشغيل GitHub Actions إثباتًا متاحًا.

## حدود التشغيل

- لم تُنشأ أو تُحذف بيانات إنتاج، ولم يُرسل بريد أو SMS.
- لم يُنشر تعديل حاجز OTP؛ التغيير محلي فقط حتى يُراجع ويُنشر عبر مسار النشر المعتاد.
- لم تُختبر المصادقة الحقيقية أو العمليات المالية على المستخدم الحالي.

## قرار الإصدار

**ويب/PWA: جاهزية مشروطة.** البناء والاختبارات المؤتمتة ورحلات العرض ناجحة، لكن يلزم اجتياز اختبارات STAGE للكتابة والعزل والاستعادة قبل قرار Go.

**تطبيق Expo الأصلي: غير جاهز للإصدار** ضمن قرار تعطيل دخول الجوال الحالي؛ يلزم استبعاده من النشر أو دعم البريد واختبار مسار الدخول الجديد.
