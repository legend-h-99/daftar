# تفعيل الدخول والتسجيل برقم الجوال (Authentica)

يرسل [Authentica](https://portal.authentica.sa) رمز التحقق برسالة SMS ويتحقق منه
(`send-otp` و`verify-otp`، التوثيق: https://docs.authentica.sa). نفس الخطوات
تُستخدم للدخول والتسجيل: أول تحقق ناجح لرقم جديد ينشئ الحساب ويحوّله لصفحة
الإعداد، والرقم المسجل سابقًا يدخل مباشرة.

دخول الجوال متوقف افتراضيًا. لا يظهر خيار الجوال في صفحة الويب إلا مع
`NEXT_PUBLIC_PHONE_LOGIN_ENABLED=true`، ولا يقبل الخادم طلبات الرمز إلا مع
`PHONE_LOGIN_ENABLED=true` **و** `AUTHENTICA_API_KEY`.

## 1. إعداد التطبيق في Authentica

1. سجّل في https://portal.authentica.sa وأنشئ تطبيقًا من
   **Applications → Create** (https://portal.authentica.sa/applications/create).
2. في إعدادات التطبيق اختر:
   - القناة الافتراضية: **SMS**.
   - طول الرمز: **6 أرقام**. الافتراضي في Authentica 4 أرقام، فغيّره (أو اضبط
     `AUTHENTICA_OTP_LENGTH` ليطابق ما تختاره، بين 4 و8).
   - صلاحية قصيرة للرمز (مثل 5 دقائق).
   - قالب الرسالة **العربي** رقمه **2**؛ القالب 1 (الافتراضي) إنجليزي.
   - اسم المرسل: الافتراضي من Authentica، أو اسم «دفتر» إن سجّلته معهم.
3. انسخ **API Key** للتطبيق. هذا مفتاح سري: لا تضعه في GitHub أو Cloudflare
   Pages أو أي متغير يبدأ بـ `NEXT_PUBLIC_`.
4. اشحن رصيدًا كافيًا (يمكن متابعته من `GET /balance`).

## 2. أسرار Supabase Edge Function

من Supabase: **Edge Functions → api → Secrets** (أو بالأمر
`supabase secrets set`):

| السر | القيمة |
|---|---|
| `AUTHENTICA_API_KEY` | مفتاح التطبيق من Authentica |
| `AUTHENTICA_TEMPLATE_ID` | `2` (العربي؛ الافتراضي 1 إنجليزي) |
| `AUTHENTICA_OTP_LENGTH` | طول الرمز كما في Authentica (الافتراضي 6) |
| `PHONE_LOGIN_ENABLED` | `true` |
| `SMS_DAILY_SEND_CAP` | سقف الرسائل اليومي (الافتراضي 100) |

بعد ضبط الأسرار أعد نشر الدالة `api`.

## 3. الواجهة

اضبط `NEXT_PUBLIC_PHONE_LOGIN_ENABLED=true` في متغيرات بناء Cloudflare Pages ثم
انشر نسخة جديدة. يظهر حقل الجوال تحت زر Google، ثم صفحة `/otp` لإدخال الرمز.

## 4. الاختبار قبل الإتاحة

1. فعّل السر في الخادم أولًا، واختبر برقمك من نسخة معاينة قبل تفعيل الواجهة للجميع.
2. تأكد من: وصول الرسالة بالعربي، رفض رمز خاطئ، دخول الرمز الصحيح، وإنشاء
   حساب جديد يذهب لصفحة الإعداد.

محليًا: `pnpm --filter api start:dev` مع `AUTH_DEV_OTP=true` يعيد الرمز في
الاستجابة دون إرسال SMS، وإعداد `web-phone` في `.claude/launch.json` يشغّل الواجهة
وخيار الجوال ظاهر.

## الحماية

- الرقم يجب أن يكون سعوديًا بصيغة `+9665xxxxxxxx`.
- 3 طلبات إرسال و5 محاولات تحقق في الدقيقة لكل رقم ولكل عنوان IP، إضافة إلى
  سقف الرسائل اليومي للتطبيق.
- لا يرجع الخادم الرمز إلى المتصفح، ولا يكتب الرقم أو المفتاح في السجلات.
- إذا رفض Authentica المفتاح أو تعطل، يرد الخادم بـ 503 («غير متاح الآن») بدل
  «رمز خاطئ»، ويظهر الخطأ في سجل أخطاء لوحة الإدارة.
