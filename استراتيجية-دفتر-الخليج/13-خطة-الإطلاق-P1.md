# خطة الإطلاق P1 — قائمة مهام تنفيذية

*الأسابيع ٢–٤ · مؤسّس فرد · أقل تكلفة · من «MVP تجريبي» إلى «منتج قابل للإطلاق»*

## الهدف
إطلاق ناعم (Soft Launch) لدفتر على **الويب + أندرويد** بميزانية **< ٢٠٠ ريال إطلاق + ~٤٠ ريال/شهر**، مع OTP حقيقي ومراقبة ونسخ احتياطي والتزام PDPL أساسي. iOS مؤجَّل لـP2.

**تعريف «تم» لـP1:** مستخدم حقيقي يسجّل برقمه → يستقبل OTP فعليًا → ينشئ فاتورة → يشاركها → يرى ربحه — كل ذلك على بيئة إنتاج مستقرّة ومراقَبة.

## المرحلة صفر — تجهيز مسبق (يوم واحد)
- [ ] **نطاق:** سجّل `daftar.sa`/`.com` (~٥٠ ر) واربطه بـCloudflare (DNS مجاني).
- [ ] **حسابات مجانية:** Vercel · Supabase (أو Neon) · Sentry · PostHog · GitHub (المستودع جاهز).
- [ ] **حساب Meta for Developers** + رقم WhatsApp Business (للـOTP عبر Cloud API).
- [ ] **حساب Google Play Console** (~٩٥ ر مرة واحدة).
- [ ] **وثيقة عمل حر** للمؤسّس (إن لم تكن جاهزة).
- **القبول:** كل الحسابات مفعّلة ومتغيّرات الأسرار مجموعة في مدير أسرار/ملاحظة آمنة.

## الأسبوع الأول — الـOTP الحقيقي + قاعدة وAPI الإنتاج

### 1) ربط مزوّد OTP (الأهم) 🔴
- [ ] أنشئ واجهة مجرّدة `OtpChannel` في `apps/api/src/auth/` (send(phone, code)).
- [ ] نفّذ `WhatsAppOtpChannel` عبر **WhatsApp Cloud API** (أول ١٠٠٠ محادثة/شهر مجانًا) — استبدل `// TODO: hand the code to the SMS gateway` في `auth.service.ts`.
- [ ] أبقِ `MockOtpChannel` خلف علم بيئة `OTP_MODE=mock|whatsapp` للتطوير/التجريب.
- [ ] (بديل احتياطي) نفّذ `SmsOtpChannel` عبر Taqnyat/Unifonic لاحقًا خلف نفس الواجهة.
- **القبول:** رقم حقيقي يستقبل رمزًا فعليًا ويسجّل الدخول · وضع mock يظل يعمل بـ`OTP_MODE=mock`.
- **الوقت:** ~١–٢ يوم · **التكلفة:** ٠ (ضمن المجاني).

### 2) قاعدة بيانات الإنتاج
- [ ] أنشئ مشروع Postgres على Supabase/Neon (طبقة مجانية).
- [ ] `prisma migrate deploy` على قاعدة الإنتاج (لا `migrate dev`).
- [ ] **لا تشغّل seed الديمو على الإنتاج** — أبقِ الحسابات التجريبية للتطوير فقط (أو seed منفصل معلّم).
- **القبول:** المخطط مطبّق، الاتصال يعمل، لا بيانات ديمو في الإنتاج.

### 3) نشر الـAPI
- [ ] انشر NestJS على **VPS صغير (Hetzner ~€4.5)** أو Railway: `pnpm --filter api build` ثم `node dist/src/main`.
- [ ] اضبط متغيّرات البيئة: `DATABASE_URL` · `JWT_SECRET` (قوي) · `CORS_ORIGIN` (نطاق الويب الإنتاجي) · `OTP_MODE=whatsapp` + أسرار WhatsApp.
- [ ] فعّل HTTPS (Cloudflare/عكسي Nginx + Let's Encrypt).
- **القبول:** `GET /api/health` أو `/auth/otp/request` يعمل عبر HTTPS من النطاق.

## الأسبوع الثاني — الويب + المراقبة + النسخ الاحتياطي + PDPL

### 4) نشر الويب
- [ ] اربط المستودع بـVercel، الجذر `apps/web`.
- [ ] اضبط `NEXT_PUBLIC_API_URL=https://api.daftar.sa/api`.
- [ ] تأكّد من عمل تسجيل الدخول → الداشبورد → الفواتير على الإنتاج.
- **القبول:** المسار الكامل يعمل على النطاق الإنتاجي (لا localhost).

### 5) المراقبة والقياس (مجاني)
- [ ] **Sentry** (DSN) في الويب + API + الموبايل — تتبّع الأخطاء.
- [ ] **PostHog** (مجاني) — أحداث: تسجيل، أول فاتورة (Activation)، فتح تقرير الربح، ترقية.
- **القبول:** خطأ مُتعمَّد يظهر في Sentry · حدث «أول فاتورة» يظهر في PostHog.

### 6) النسخ الاحتياطي
- [ ] فعّل النسخ التلقائي (Supabase يوفّره) **أو** `pg_dump` عبر cron يومي → Cloudflare R2 (مجاني حتى حد).
- [ ] اختبر **الاستعادة** مرة واحدة (نسخة لا تُختبر = لا نسخة).
- **القبول:** نسخة يومية موجودة + استعادة ناجحة مجرَّبة.

### 7) الخصوصية (PDPL — أساسي)
- [ ] صفحة **سياسة خصوصية** عربية (ما يُجمع، لماذا، حقوق المستخدم).
- [ ] **موافقة صريحة** عند التسجيل + رابط السياسة.
- [ ] **تصدير/حذف بيانات** المستخدم (نقطة نهاية بسيطة أو طلب يدوي موثّق مبدئيًا).
- [ ] تشفير أثناء النقل (HTTPS ✅) وتقليل جمع البيانات.
- **القبول:** سياسة منشورة · موافقة مسجّلة · مسار حذف موثّق.

## الأسبوع الثالث — أندرويد + اختبار شامل

### 8) نشر أندرويد
- [ ] `eas build -p android` (EAS طبقة مجانية) → ملف AAB.
- [ ] ارفع على Google Play → **Internal testing** أولًا (دائرة صغيرة).
- [ ] جهّز صفحة المتجر: أيقونة، لقطات (من الشاشات المُعاد تصميمها)، وصف عربي، سياسة الخصوصية (مطلوبة).
- **القبول:** التطبيق يُثبَّت من Internal testing ويعمل مع API الإنتاج.

### 9) اختبار end-to-end (على الإنتاج)
- [ ] المسار الحرج: تسجيل برقم حقيقي → OTP → إنشاء نشاط → فاتورة → مشاركة واتساب → تقرير ربح → «لي عند».
- [ ] اختبر على جوال حقيقي (أندرويد) + متصفح جوال.
- [ ] أصلح ما يظهر من أخطاء (Sentry).
- **القبول:** المسار الحرج يعمل بلا أخطاء على جهازين مختلفين.

## الأسبوع الرابع — إطلاق ناعم + أول مستخدمين

### 10) الإطلاق الناعم (Soft Launch)
- [ ] ادعُ **٥–١٠ مستخدمات حقيقيات** (من شبكتك/مجموعات واتساب) — لا إعلانات بعد.
- [ ] راقب Activation (أول فاتورة/٢٤س) وأي احتكاك.
- [ ] دعم مباشر عبر واتساب — دوّن كل سؤال متكرر (→ أسئلة شائعة لاحقًا).

### 11) القياس والتعلّم
- [ ] لوحة PostHog: تسجيل → Activation → فتح الربح → عودة D1/D7.
- [ ] قابل ٢–٣ مستخدمات (١٥ دقيقة) — أين تعثّرن؟
- **القبول:** بيانات أول أسبوع مجمّعة + قائمة أهم ٣ احتكاكات.
