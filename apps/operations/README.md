# غرفة عمليات دفتر

تطبيق خاص بالمالك في `apps/operations`، منفصل عن موقع العملاء وعن ملفات `ops/` السابقة. الواجهة والخادم Next.js، والعامل عملية مستقلة، والحالة محفوظة في PostgreSQL. لا تحتاج المحادثة أو المتصفح للبقاء مفتوحين.

## ما يعمل

- ثمانية أقسام و17 دورًا، أهداف أسبوعية معتمدة، مهام بمسؤول ومراجع ومعيار قبول.
- دورة إنشاء مسودة → مراجعة مستقلة → إغلاق بالمالك مع أدلة. اقتراحات المتابعة تحت الهدف نفسه، بحد أقصى ثلاثة ولمستوى واحد.
- جدولة الساعة 09:00 الرياض؛ مهمة لكل قسم/هدف، مع منع تكرار الجدولة وتراكم عمل جديد فوق غير المكتمل.
- نموذج دعم عام في `/support` بموقع دفتر. يحفظ بريد الرد والوصف، ويعيد رقمًا فقط. التصنيف يربط الطلب بمهمة ضمن هدف معتمد. يمكن تعيين هدف الدعم من الصندوق لمعالجة الطلبات تلقائيًا طوال اليوم داخل أسبوع الهدف؛ دون تعيينه تبقى المتابعة يدوية.
- إجراءات مع بصمة محتوى ووجهة. تعديلها يبطل الموافقة ويلغي الإرسال المنتظر. لا يصل النموذج إلى أدوات الاعتماد أو الإرسال.
- بريد Resend بعد موافقة المالك؛ النشر والصرف والدمج والنشر الإنتاجي تنفذ يدويًا بعد الاعتماد وتوثق بإيصال. لا توجد موصلات اجتماعية مخفية.
- استدعاءات OpenAI ذات JSON schema عبر adapter قابل للاستبدال. لا يعمل دون مفتاح ونموذج وتسعير وسقف معتمد. محتوى الدعم يعامل بيانات، ولا يُمرّر بريد العميل إلى النموذج.
- تغييرات كود ضمن مسارات محددة؛ نسخة نظيفة من commit مع فرع مستقل داخل مجلد مؤقت، Docker بلا شبكة أو أسرار وبصلاحيات محدودة، فرق كود وسجل اختبارات. لا يُنفذ كود النموذج على المضيف. النموذج لا يختار أمر الاختبار.

## إعداد محلي أو على خادم خاص

يتطلب Node 22+ وpnpm 10.33.2 وPostgreSQL 15+؛ Docker مطلوب لاختبارات الكود المعزولة فقط.

1. أنشئ قاعدة مستقلة. للتطوير المحلي دون Docker أو حساب سحابي يمكنك تشغيل `pnpm --filter @daftar/operations db:local` وتركه يعمل؛ يحفظ البيانات في `.local/pgdata` خارج git ويستمع محليًا فقط بلا مصادقة، ويستخدم اتصال المثال. ليس بديلًا عن PostgreSQL/Supabase للإنتاج. **لا تستخدم قاعدة بيانات المحاسبة لتطبيق `db/001_operations.sql`.**
2. انسخ `.env.example` إلى `.env.local` داخل التطبيق. أدخل اتصال قاعدة العمليات، `OPS_ORIGIN` وعنوان بريد المالك.
3. شغّل `pnpm --filter @daftar/operations password`، أدخل كلمة مرور طويلة في stdin ثم EOF. احفظ القيم الناتجة في ملف البيئة الخاص؛ لا تضعها في المحادثة أو git. على الطرفية، عطّل echo قبل إدخال كلمة المرور إذا كان تسجيل الطرفية مفعلًا.
4. بعد التحقق من وجهة قاعدة البيانات:

```sh
OPS_ALLOW_MIGRATION=dedicated-operations-database pnpm --filter @daftar/operations migrate
pnpm --filter @daftar/operations dev
pnpm --filter @daftar/operations worker
```

يمكن تجهيز هدف الإطلاق وثماني مهام مقترحة محليًا بالأمر `pnpm --filter @daftar/operations bootstrap:local`؛ لا يعتمد هذا الأمر الأهداف أو الميزانية، ويحافظ على الأهداف الموجودة.

الواجهة على `http://localhost:3100`. يبدأ النظام متوقفًا والتكلفة المدفوعة غير مفعلة. سجّل الدخول، أنشئ هدف الأسبوع، اعتمده، ثم راجع [تقدير التكلفة](COSTS.md) واضبط الموصلات والميزانية واستأنف التشغيل.

للإنتاج: `pnpm --filter @daftar/operations build` ثم `start` وعملية `worker` تحت مدير خدمات يعيد تشغيلهما. استخدم HTTPS ونطاقًا مستقلًا؛ لا يصلح التطبيق كـ static export على Cloudflare Pages. اضبط أسرار البيئة على الخادم لكلتا العمليتين. قاعدة Supabase عبر اتصال PostgreSQL الخادمي مع TLS؛ لا تُرسل service-role keys للمتصفح. استخدم مستخدم قاعدة مخصصًا يملك جداول العمليات فقط. RLS يمنع anon/authenticated؛ اتصال التطبيق المالك هو مسار الوصول.

## الموصلات

### النماذج والميزانية

اضبط `OPENAI_API_KEY`، `OPS_MODEL`، `OPS_INPUT_SAR_PER_MILLION` و`OPS_OUTPUT_SAR_PER_MILLION` بعد اختبار توافق النموذج مع Chat Completions وStructured Outputs. الأسعار بوحدة ريال/مليون رمز، وتُختار بما يغطي رسوم المزود الفعلية (والإضافات إن وجدت). قبل كل طلب يحجز النظام حدًا محافظًا: عدد بايتات UTF-8 المسموح + هامش framing، و5,000 رمز مخرجات. الاستجابة تسوّي الاستخدام الفعلي؛ عند غياب الاستجابة يبقى الحجز محفوظًا. لا تستخدم adapter لإجراء tool calls مدفوعة خارج هذا الحجز.

`monthly_cap_micro` يجمع استهلاك/حجوزات النماذج والبريد في شهر الرياض. لا يمثل فاتورة الاستضافة الثابتة أو ميزانية الإعلانات. سقف المزود الخارجي يبقى طبقة حماية إضافية؛ تغيير تسعير المزود يحتاج تحديث الإعدادات قبل التشغيل. توقف المهام التي لا تكفي ميزانيتها بدل تكرار طلبات مدفوعة.

### بريد الدعم

اضبط `RESEND_API_KEY` و`OPS_SUPPORT_FROM` لنطاق إرسال موثق و`OPS_EMAIL_MAX_SAR` لحد محافظ لتكلفة الرسالة. يتطلب الإرسال التفعيل والميزانية والموافقة المحددة. عنوان المستلم يُستمد من التذكرة خادميًا. المفتاح الثابت لكل إصدار يمنع التكرار. النتيجة المجهولة لا يعاد إرسالها تلقائيًا؛ تحقق من سجل المزود ووثّق النتيجة في لوحة الموافقات. لا تُفسّر موافقة Telegram القديمة كإذن هنا.

### نموذج موقع دفتر

اضبط عند بناء موقع العملاء:

```text
NEXT_PUBLIC_OPS_SUPPORT_URL=https://ops.daftar1.com/api/support
```

النطاق الافتراضي المقترح لغرفة العمليات هو `ops.daftar1.com`؛ إعداد DNS والنشر منفصلان. سياسة CSP لتصدير Cloudflare تسمح بهذا النطاق صراحة؛ عند اختيار نطاق آخر عدّل connect-src في `apps/web/public/_headers` معه. إعداد Next الخادمي يستخرج الأصل المسموح من رابط الدعم الصحيح.

اضبط `OPS_SUPPORT_ORIGIN=https://daftar1.com` في العمليات. الطلبات JSON وبلا cookies. يتطلب أصلًا مطابقًا وحجمًا محدودًا، مع honeypot وحدود مخزنة في القاعدة. إذا كان النطاق النهائي `www` فاضبط الأصل وفقًا له. دون endpoint تعرض الصفحة أن النموذج غير مفعل ولا تدعي إرسال طلب.

إذا كان التطبيق خلف reverse proxy موثوق، اضبط `OPS_TRUSTED_IP_HEADER` على اسم رأس يستبدله البروكسي دائمًا. بدونه يستخدم النظام حدًا مشتركًا محافظًا؛ لا يثق تلقائيًا بـ X-Forwarded-For القادم من الإنترنت. أضف حدًا على مستوى البروكسي للمدخل العام. لا تخزن عناوين IP الخام.

### مؤشرات دفتر

الموصل الاختياري `supabase/functions/operations-metrics` مع migration `20261020100000_operations_metrics.sql` يُراجع وينشر **بشكل منفصل** إلى دفتر، ولا ينشره migrate الخاص بالعمليات. الدالة SQL ثابتة للقراءة فقط ولا تستخدم `admin_overview()` الذي يحذف أحداثًا قديمة. تستبعد حسابات demo المعروفة ويمكن تحديد حسابات المؤسس/الاختبار بـ `OPS_EXCLUDED_USER_IDS` في أسرار دالة المصدر.

أنشئ `OPS_METRICS_TOKEN` عشوائيًا لا يقل عن 32 حرفًا، مختلفًا عن service role. ضع نفس التوكن في دالة المصدر وخادم العمليات، واضبط `OPS_METRICS_URL` على رابط الدالة. تُنشر الدالة بـ `--no-verify-jwt` لأنها تتحقق من bearer خاص. لا تعيد إلا مجاميع محددة. عدادات الحسابات لا تثبت عملاء فعليين، والإيرادات غير مقاسة؛ القاعدة الأصلية تبقى المصدر.

### بيئة تطوير معزولة

ابنِ صورة موثوقة مسبقًا من جذر المستودع:

```sh
docker build -f apps/operations/Dockerfile.sandbox -t daftar-ops-tests:local .
```

اضبط `OPS_REPO_PATH` إلى checkout مصدر موثوق، و`OPS_SANDBOX_IMAGE=daftar-ops-tests:local`، و`OPS_ARTIFACTS_DIR` إلى مجلد خاص خارج مستودع المنتج. الأفضل عامل مخصص غير حامل لمفاتيح إنتاج. يجب أن تكون الصورة محلية؛ العامل لا يسحبها من الشبكة.

اكتب مسارات ملفات المصدر في سياق المهمة، مثل `apps/web/components/TopBar.tsx`. يسمح بتعديل TS/TSX/CSS تحت app/components/lib/__tests__ فقط، وفي المسارات التي حددتها. يحظر ملفات البيئة والحزم وCI والمسارات الخارجة. احتفظ بتحديث صورة dependencies عند تحديث lockfile.

المعاينة المتاحة هي فرق الكود ونتائج الاختبار، لا رابط نشر. احفظ patch عند مراجعته ثم طبقه على فرع مراجعة. يجب أن يظل HEAD المصدر مطابقًا للـ base عند إغلاق مهمة الهندسة واعتماد الدمج/النشر؛ وإلا تُعاد المهمة والاختبارات. لا يجري النظام merge أو deploy تلقائيًا.

## الاختبارات والتشغيل

```sh
pnpm --filter @daftar/operations typecheck
pnpm --filter @daftar/operations test
pnpm --filter @daftar/operations build
```

الاختبارات تشغّل SQL فعليًا عبر PGlite وتستبدل مزود النموذج والبريد ببدائل اختبار؛ لا تُصرف أموال ولا تُرسل رسائل. الفحص المرئي يستخدم بيانات اختبار محلية مستقلة: بعد البناء شغّل `pnpm --filter @daftar/operations test:browser` (يلزم Chromium لـ Playwright). يجب تنفيذ اختبار Docker واختبار موصلات الإنتاج بالحسابات المناسبة قبل إعلان جاهزية التشغيل المتصل.

الـ lease خمس دقائق، طلب النموذج 90 ثانية، واختبار الحاوية دقيقتان. محاولات استرجاع المهام المنقطعة بحد أقصى ثلاثة. الأخطاء العادية تُرفع للمالك لإعادة التشغيل، ولا تدور في حلقة مدفوعة. إيقاف التشغيل يلغي المنتظر؛ الطلب الشبكي الجاري قد يكتمل وتظل نتيجته مسجلة. التشغيل يحتاج جهازًا/خادمًا مستمرًا؛ إغلاق عملية العامل يوقف المعالجة حتى إعادة تشغيلها.

## الحدود الحالية

- لا اتصالات اجتماعية أو توليد صور/فيديو مدفوع؛ دور المصمم ينتج مواصفات ومسودات محتوى للمراجعة.
- المراجعة اللغوية بالنموذج مساعدة؛ المالك يتحقق من صحة المصادر والنتائج قبل الإغلاق أو التنفيذ.
- تذاكر الدعم والمخرجات محفوظة إلى أن تُطبق سياسة احتفاظ معتمدة؛ لا تنسخها إلى git. النسخ الاحتياطي والاستعادة مسؤولية إعداد قاعدة البيانات.
- لا تحتوي نسخة البناء على مفاتيح أو حسابات جديدة. الربط المدفوع والنشر الإنتاجي يتطلبان إعدادات واعتماد المالك.
